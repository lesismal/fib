fib 架构说明

fib（Fast In Balance）是边沿触发的事件循环加协程池：循环只等事件，把变为可执行的连接动态调度到逻辑 worker 上，连接的每一轮（读、回调、写）都在 worker 上执行。本文说明 Go 实现的整体结构，依据 main（8a388d4）的源码；各协议的逐步流程见协议流程图。

事件循环（根 / poller） ‹Name›-workers 引擎池 fib-tls-handshake 握手池 ‹Name›-streams 流池 定时器 goroutine 用户自己的 goroutine

三条不变量

整个并发模型靠这三条规则推理。其余设计都是它们的推论。

fd 归事件循环

只有循环做 epoll_ctl、accept 和最终的 close(fd)。worker 想暂停读、关闭连接或释放 fd，都通过命令队列加 eventfd 告诉循环，循环醒着时不需要唤醒。

顺序归连接

调度单位是连接，不是事件。循环把就绪事件并入连接的 pendingEvents，scheduled 为真时不再投递。同一时刻一条连接最多一个 worker，OnData 不会并发也不会乱序，OnClose 总在之前的 OnData 之后。

连接不绑定线程

每一轮由当时空闲的 worker 领取，这一轮和下一轮可能是不同的 goroutine。均衡的对象是待执行的工作量，不是连接数。

组成

一个 Engine 拥有监听器、事件循环、命令队列和 worker 池。开启 IOPollers（CPU 多于 4 个时默认开启）时，它还拥有若干 poller：每个 poller 是一个没有监听器的 Engine，有自己的循环、命令队列和 fd 表，配置、handler、worker 池和全局预算与父 Engine 共用。

  • worker 数是上限而不是常驻数量：Adaptive 池在任务发现所有 worker 都忙时增长，按间隔把一直空闲的 worker 减半回收。把上限设高没有成本，设低会限制突发。
  • worker 自己做读写系统调用，很多时间在内核里而不在 P 上，所以池相对核数是超额配置的。GOMAXPROCS 保持运行时默认值（核数）最好。
  • 三个池互相独立：引擎 worker 可以等流池和握手池的队列，反过来从不发生，所以不会出现所有 worker 都卡在提交上的死锁。

读取与调度

从内核事件到业务回调，再回到可再次调度的状态。循环一轮提交一批连接，而不是每条连接一次加锁和唤醒。

  C --> D["runReady<br/>GoTasks 整批提交<br/>runtime.Gosched 让出 P"]

  • 事件合并：就绪对连接来说是电平信息，重复通知按位或在一起，热连接不会攒出无界的事件队列。只有 EPOLLOUT 且没有排队输出的通知直接丢弃，避免每条新连接被多调度一次。
  • 让出 P：提交后循环先 Gosched，刚唤醒的 worker 立刻用上这个 P。4 个 P、1 万连接的 HTTP/2 echo 上这一步提升 10% 到 25%。
  • 循环不占 P：开启 IOPollers 时，循环停在 Go 运行时的网络轮询器里等待，而不是阻塞在 epoll_wait 系统调用里。
  • 读缓冲按轮借用：16KB 读缓冲每轮从 bufferpool 取、轮末归还，空闲连接不占读缓冲。短读说明 socket 已空，不再多读一次去拿 EAGAIN。
  • UDP 例外：共享的 UDP socket 由循环自己读（批量收包），按对端地址把数据报放进各 peer 连接的队列，worker 的一轮只负责把队列交给 handler。

写路径与背压

能直接写就直接写，写不完才排队。排队的字节数有两道界限：每条连接的水位和整个 Engine 的总预算，越界时暂停的是读，让 TCP 流控去限制对端。

  • 写关注常驻：EPOLLOUT 从注册起一直开着，排队本身不需要改注册，只有越过水位才需要一次 epoll_ctl。
  • cork：一轮之内的回复先攒在一个连续缓冲里，轮末一次写出。流式响应想先把前一部分发出去时调 Flush；应用也可以自己 Cork。
  • 滞回：暂停在高水位（默认 64KB），恢复在其 1/4，避免每个回复都来回越线；总预算（默认 1GiB）同样在 1/4 处恢复。连接数很多时真正起作用的是总预算。
  • 被总预算暂停的连接自己可能没有任何待发数据，不会有自己的事件来重新评估，所以循环把它们记在 budgetPaused 里，预算回落时统一恢复；释放预算的连接在别的 poller 上时会唤醒这些循环。
  • 读侧背压：HoldReads 让应用在自己消化不完时暂停读（流式请求 body 就是这样用的），释放后重新交付 socket 里已有的字节。
  • Stats() 报告两种暂停各发生多少次、已恢复多少次和当前排队总量；SendFile 走 sendfile，不计入预算。

  • 一轮还在 worker 上跑时，它读写的 fd 不会被关闭，也就不会被内核分给别的连接。
  • fd 复用由代次防护：token 低 32 位是 fd，高 32 位是代次，旧连接遗留的事件解析不到新连接。

  • Engine 关闭时先停循环和 poller，等在跑的轮次结束，再执行欠下的最后一轮，保证已关闭连接的 OnClose 不丢。

负载均衡

连接数均分不等于工作量均分：少数热连接或重任务可能集中在同一个线程上。fib 在四个层次上处理这件事。

层次做法代价与取舍
worker连接每一轮由空闲 worker 领取，没有亲和性；Adaptive 池按 P 分片入队，批量提交阻塞的 handler 只拖住自己的连接，池会增长来吸收
polleraccept 到的连接按 fd % pollerCount 分配；poller 只等事件，每请求约 0.2µs，worker 约 4.5µspoller 多了会和 worker 抢 P：每 4 个 CPU 一个是默认值
accept默认由根循环 accept 再分发；Linux 上 ReusePort 让每个 poller 自己 listen、自己 acceptReusePort 解除单循环的 accept 上限，但连接留在内核哈希选中的 poller 上，不管它多忙
多路复用HTTP/2、HTTP/3 的 handler 进流池，一条连接上的请求并发执行MaxConcurrentHandlers 可限制单连接并发，超限的在读者上执行

缓冲与内存

  • bufferpool 是包级的、进程内共享的池：容量都是 2 的幂，正好落在 Go 分配器的尺寸类上，不为取整付费；每个类在 sync.Pool 后面留一份不受 GC 清空的储备。
  • 读缓冲 16KB，按轮借用；数据在 OnData 期间借给 handler，协议解析器直接在上面解析，剩余的才复制。
  • 发送缓冲 取 2 倍读缓冲大小对齐到池的类，容纳一轮的回复；被单条大消息撑大的缓冲回到它容量所属的类，不会污染普通缓冲。
  • 连接表 是按 fd 索引的分页表（每页 4096 项），查找是两次边界检查而不是哈希；只在页目录上扩容。
  • TLS 握手后不保留 crypto/tls 的缓冲，记录直接从本轮的读缓冲解密；UDP 数据报逐个从池里取缓冲，QUIC 用完归还。

平台后端

引擎的其余部分只依赖就绪模型，三个后端把各自观察到的东西翻译成同一组事件位，worker、排队和背压在所有平台上是同一份代码。

平台后端要点
Linuxepoll，边沿触发，eventfd 唤醒IOPollers、ReusePort 分摊 accept 和 UDP；读写是原始系统调用，SocketSyscalls 时走 recvfrom / sendto / sendmsg；UDP 用 recvmmsg / sendmmsg
macOSkqueue支持 IOPollers；SO_REUSEPORT 不在多个 socket 间分摊 TCP 连接，accept 仍在根循环
WindowsI/O 完成端口零字节重叠 WSARecv 充当读边沿，重叠 WSASend 的完成充当写边沿；保持单个循环，忽略 IOPollers
其他*_other.go基于标准库的回退实现，每条连接一个 goroutine，API 相同
