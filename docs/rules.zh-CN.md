# fib 开发规则

[English](rules.md) | 简体中文

fib 的每个改动都遵守的规则，与代码如何组织和验证（[路线图](roadmap.zh-CN.md)、[压测](loadtest.zh-CN.md)）并列。

## 1. 清理

1. **每次开发、测试和基准运行结束后都要清理自己留下的东西，释放占用的空间。** 工作完成后（一个功能、一次修复、一次
   测试或基准运行、一次复现），清除它在本机和基准测试主机上留下的东西：为它产生的构建输出（二进制、`go test -c`
   生成的测试二进制、压测构建）、源码树副本和 git worktree、它创建的容器、镜像和卷，以及不再需要的日志和临时文件。
   有意保留的缓存（Go 的构建和模块缓存、固定版本的镜像）保留，但增长后要修剪。基准测试主机的磁盘由所有会话共用：
   大规模构建或运行前先查看剩余空间（`df -h /`），离开时不要比来时更满；磁盘写满会让所有人的构建和运行停下。
